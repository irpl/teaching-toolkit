# Document / Written Assignment Grading

Grades research papers, essays, reports, and other written submissions. Follows the shared /grade workflow for feedback and tracking.

## Extracting Content from PDF Files

Claude Code can read PDF files directly using the Read tool with a `pages` parameter. For large PDFs, read in chunks of up to 20 pages at a time.

```
Read file_path: "path/to/file.pdf"               # small PDFs (≤10 pages)
Read file_path: "path/to/file.pdf" pages: "1-20"  # first 20 pages
Read file_path: "path/to/file.pdf" pages: "21-40" # next 20 pages
```

- Always read the full document before grading — paginate through if needed.
- PDF content is extracted as text — formatting details (fonts, spacing, margins) may not be fully visible. Note this limitation in feedback if the rubric assesses formatting.
- For APA/formatting checks, a .docx submission is preferred. If only a PDF is provided, assess formatting based on what is visually apparent but note that deep checks (heading styles, real citations vs typed, auto-generated TOC) cannot be verified.

## Extracting Content from .docx Files

.docx files are ZIP archives containing XML. Use Python to extract:

```python
import zipfile
import xml.etree.ElementTree as ET

z = zipfile.ZipFile(r'path\to\file.docx')

# Read main content
content = z.read('word/document.xml')
root = ET.fromstring(content)
xml_str = content.decode('utf-8')

# Get page count from metadata
try:
    app_xml = z.read('docProps/app.xml')
    app_root = ET.fromstring(app_xml)
    for elem in app_root.iter():
        if 'Pages' in elem.tag:
            page_count = elem.text
except:
    pass

# Extract all text content
ns = {'w': 'http://schemas.openxmlformats.org/wordprocessingml/2006/main'}
paragraphs = root.findall('.//w:p', ns)
for p in paragraphs:
    texts = [t.text for t in p.findall('.//w:t', ns) if t.text]
    print(' '.join(texts))
```

### Checking Word Features in XML

| Feature | What to look for in XML |
|---------|------------------------|
| Heading styles | `pStyle` attribute with value `Heading1`, `Heading2`, etc. |
| Table of Contents | `TOC` in `w:instrText` elements (auto-generated, not manually typed) |
| Citations | `CITATION` tags in XML (Word citation feature, not manually typed) |
| Bibliography | Generated by Word's bibliography tool |
| Formulas in tables | `w:instrText` containing `=SUM`, `=AVERAGE`, `=MIN`, `=MAX` |
| Mail merge fields | `MERGEFIELD` in XML (real merge fields, not typed chevron placeholders) |
| Page numbers | Header XML with page number field |

## What to Assess

Grade against the rubric provided. If no rubric is given, use these general criteria and ask the user for marks allocation:

### Content and Research
- Depth and accuracy of content
- Use of credible sources (peer-reviewed, textbooks, reputable websites)
- Evidence of critical thinking and analysis
- Coverage of required topics

### Structure and Organisation
- Logical flow of ideas
- Clear introduction, body, and conclusion
- Appropriate use of headings and subheadings
- Paragraph structure and transitions

### Formatting (if APA or other style required)
- Title page with required elements
- Running head and page numbers
- Font, spacing, margins, indentation
- In-text citations formatted correctly
- Reference list formatted correctly (hanging indent, alphabetical)
- Minimum page/word count met

### Writing Quality
- Spelling and grammar
- Clarity and readability
- Professional academic tone
- No plagiarism indicators (sudden style shifts, inconsistent formatting)

### Word Features (if required by rubric)
- Use of Word's built-in tools (citation manager, TOC generator, heading styles)
- Verify these through XML inspection — students sometimes fake them manually
- Check: auto-generated TOC vs typed, real citations vs typed "(Author, Year)", real merge fields vs typed chevrons

## Common Issues to Watch For

1. **Fake features** — typed table of contents, typed citations, typed merge field placeholders instead of using Word's built-in tools. Always verify through XML.
2. **Page count padding** — excessive spacing, oversized fonts, unnecessary images to meet page requirements.
3. **Missing sources** — claims without citations, or citations that don't appear in the reference list.
4. **Single source reliance** — using only one source when multiple are required.
5. **Copy-paste indicators** — inconsistent formatting, font changes, or style shifts mid-document.

## AI Indicators for Document Assignments

Watch for these in addition to the general indicators in the shared /grade skill:

- **Unnaturally smooth prose** — every paragraph flows perfectly with polished transitions like "Furthermore," "Moreover," "It is worth noting that." Real student writing is choppier.
- **Overly balanced arguments** — AI tends to present "on one hand... on the other hand" structures for every point. Students usually lean one direction.
- **Generic examples** — AI uses well-known, safe examples (e.g., "companies like Amazon and Google"). Students more often use examples from class, textbooks, or local context.
- **Perfect grammar and spelling throughout** — a long document with zero typos, zero subject-verb disagreements, and zero comma splices from a student whose previous work had errors.
- **Vocabulary mismatch** — words like "multifaceted," "paradigm," "leveraging," "holistic" in a first-year paper. Check if the sophistication matches the student's course level.
- **Lack of personal voice** — reads like an encyclopedia entry rather than a student exploring a topic. No "I think," no opinions, no references to class discussions.
- **Citations that look correct but are fabricated** — author names, journal titles, or URLs that don't actually exist. If a citation looks suspiciously perfect, note it for the lecturer to verify.
- **Consistent paragraph length** — AI often produces paragraphs of very similar length (4-6 sentences each). Real student writing varies more.
- **Section quality doesn't vary** — in real student work, some sections are stronger than others (they understood some topics better). Uniform quality throughout is unusual.
